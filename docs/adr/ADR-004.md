# ADR-004: Estrategia de Pruebas de Integracion con H2 en Memoria y Gateway Mockeado

## Estado
Aceptado

## Contexto
Las pruebas de integracion tienen como proposito validar que los componentes del microservicio (controladores, servicios, repositorios de JPA, transacciones y beans de configuracion) colaboren adecuadamente entre si dentro del ApplicationContext de Spring. Sin embargo, surgen dos decisiones de infraestructura:
1. ?`Como verificar la persistencia de datos y las consultas derivadas de Spring Data JPA sin depender de un motor de base de datos relacional de produccion pesado?
2. ?`Como ejecutar el flujo completo de integracion sin realizar despachos reales de SMS a proveedores externos (como Twilio) que requieran credenciales privadas, acceso a internet o generen costos monetarios por envio?

## Decision
Se adopta una arquitectura de pruebas de integracion hibrida y pragmatica:

1. **Uso de H2 en memoria como Fake para la capa de persistencia:**
   - En `@DataJpaTest` y `@SpringBootTest`, Spring Boot autoconfigura una base de datos relacional H2 en memoria (`jdbc:h2:mem:...`).
   - H2 implementa fielmente el estandar SQL y el dialecto de Hibernate, ejecutando sentencias `CREATE TABLE`, `INSERT` y consultas complejas (`findByFechaHoraCitaBetweenAndRecordatorioEnviadoFalse`) exactamente igual que una base de datos relacional externa, sin costo de licenciamiento ni latencias de red.

2. **Uso de `@MockBean` sobre `NotificadorSmsGateway`:**
   - En la prueba de contexto completo (`CitaReminderServiceIntegrationTest`), el gateway hacia la API de SMS se sustituye mediante `@MockBean`.
   - Esto intercepta el metodo `enviarSms(numero, texto)`, impidiendo cualquier salida HTTP real hacia servicios de telecomunicaciones, al tiempo que permite verificar mediante `verify(notificadorSmsGateway, times(1))` que el adaptador de salida fue invocado con exito.

## Alternativas Descartadas

1. **Uso de Testcontainers con PostgreSQL o MySQL en CI:**
   - Descartado para el alcance del laboratorio. Aunque Testcontainers provee maxima paridad con produccion, exige un demonio de Docker corriendo en el runner de CI, elevando el tiempo de compilacion en 30 a 60 segundos por inicializacion de contenedores. Dado que las consultas de Spring Data JPA del proyecto son compatibles con el estandar JPA, H2 en memoria ofrece un retorno optimo entre velocidad y confianza.

2. **Ejecutar llamadas reales al gateway de SMS en pruebas:**
   - Descartado porque introduciria pruebas no deterministicas (flaky tests) que fallarian ante cortes de conectividad externa, requeririan secretos o tokens de API en el repositorio y generarian costos recurrentes.

## Consecuencias
- **Positivas:**
  - Pruebas de integracion rapidas (ejecucion en menos de 10 segundos) y totalmente autocontenidas.
  - El pipeline de GitHub Actions no requiere servicios auxiliares (`services:`) ni configuraciones de Docker.
  - Verificacion completa del ciclo de vida JPA (rollback transaccional automatico en `@DataJpaTest` y sincronizacion con base de datos en `@SpringBootTest`).
- **Negativas:**
  - H2 puede presentar ligeras discrepancias sintacticas con funciones especificas de motores comerciales muy avanzados, por lo que su uso debe limitarse a consultas y tipos de datos estandar de JPA.
